# uSwap v5.3.0 — Intégration du frontend sprint 5.2.0 (tag `uswap-frontend-s5.2.0`)

> Document d'intégration : ce qui a changé dans le frontend livré par le
> développeur frontend (tag **`uswap-frontend-s5.2.0`**, commit `7a6be10`), ce que
> le backend devait recevoir pour rester connecté, et les vérifications passées.

---

## 1. Contexte

Le tag `uswap-frontend-s5.2.0` (« Livraison frontend sprint 5.2.0 ») a été poussé
sur la branche `develop`. Il fait suite au merge `uswap-v5.3.0` et **remplace**
le frontend précédemment intégré.

Deux constats immédiats :

1. Le frontend est repassé en version **5.2.0** avec **Vite 6.3.5** et un jeu de
   dépendances réduit (`@dnd-kit`, `@fontsource/poppins`, `@phosphor-icons/react`,
   `xlsx`). Les dépendances `qrcode` et `leaflet` ont disparu.
2. Les écrans **QR ont été supprimés** (`QrScanner.tsx`, `QrManagement.tsx`,
   `qrToken.ts`, `ChiefHome.tsx`). Le pointage ne se fait plus par QR code mais
   par **géolocalisation GPS**.

Le backend, lui, exposait toujours l'ancien contrat (pointage par jeton QR). Il
fallait donc **réaligner le backend sur le nouveau frontend**.

---

## 2. Ce que le nouveau frontend appelle (contrat réel)

Le contrat a été extrait de la couche maquette `frontend/src/api/mock/handlers/*.ts`
(qui reproduit fidèlement le backend) et des appels `api(...)` du code.

Appels **nouveaux ou modifiés** par rapport au backend existant :

| Route attendue | Méthode | Rôle | Statut backend initial |
|---|---|---|---|
| `/attendance` (pointage GPS) | POST | SWAPPER | ❌ absent (seulement QR) |
| `/leaves/{id}/cancel` | PATCH | SWAPPER | ❌ seulement POST |
| `/admin/leaves/pending` | GET | ADMIN | ❌ absent |
| `/admin/leaves/{id}/decision` | PATCH | ADMIN | ❌ absent |
| `/operations/absences/attachments` | POST | SWAPPER | ❌ absent |
| `/plannings/{id}/occurrences/{oid}/remove` | POST | ADMIN, SUPERVISOR | ❌ seulement PATCH |

Le frontend appelle aussi `POST /shift-templates/apply`, mais **uniquement en
mode maquette** : en mode réel, il boucle sur `POST /stations/{id}/shift-templates`,
déjà exposé. Aucun changement backend n'était donc nécessaire pour cette route.

## 3. Modifications backend réalisées

### 3.1 Pointage GPS — `POST /attendance` (US-2074/2076)

**Schéma** — nouvelle colonne sur `Station` :

```prisma
geofenceRadiusMeters Int @default(150)
```

Migration : `prisma/migrations/20261004000000_v53_geofence_punch/migration.sql`.

**Service** — `AttendanceService.punch()` :
- valide `kind` (`CHECKIN` / `CHECKOUT`) et les coordonnées ;
- vérifie que le shift est **publié** et **affecté au swappeur** ;
- calcule la distance par **formule de Haversine** et compare au périmètre
  `Station.geofenceRadiusMeters` en tenant compte de la précision GPS ;
- contrôle les fenêtres horaires (prise pendant le créneau, fin tolérée +5 min) ;
- renseigne `checkInAt`/`checkOutAt` et les coordonnées dans `Attendance` ;
- renvoie exactement la forme attendue par le frontend (`PunchResult`) :
  `{ kind, status, checkedInAt, checkedOutAt?, toleranceMinutes, timezone, distanceMeters }`.

**Contrôleur** — `@Post()` sur `/attendance`, rôle `SWAPPER`. La route est
déclarée **avant** `check-in`/`check-out` et avant `GET /:id`.

> Les anciennes routes `POST /attendance/check-in` et `/check-out` (jeton QR)
> sont conservées pour compatibilité.

### 3.2 Annulation de congé par PATCH

`LeaveController` expose désormais `@Patch('leaves/:id/cancel')` en plus du
`@Post` existant. Les deux appellent le même `LeaveService.cancel()`.

### 3.3 Inbox d'administration des congés

Nouveaux endpoints :

- `GET /admin/leaves/pending` (ADMIN) — demandes `PENDING`, les plus anciennes
  d'abord, enrichies de `swapperName` et `swapperId` pour l'écran
  `LeaveRequestInbox`.
- `PATCH /admin/leaves/:id/decision` (ADMIN) — corps `{ decision, reason }`.
  Validation : décision ∈ `APPROVED | REJECTED` ; refus exigeant un motif de
  5 caractères minimum. Effets : mise à jour du statut, décrément des jours en
  attente, incrément des jours utilisés si approuvé, **notification** au swappeur.

### 3.4 Justificatif d'absence

- `POST /operations/absences/attachments` (SWAPPER, `multipart/form-data`) —
  mêmes règles que les corrections : PDF/JPEG/PNG/WebP, 5 Mo maximum, stockage
  sous `uploads/absences/`.
- `DeclareAbsenceDto` accepte désormais `attachmentId`, transmis à
  `declareAbsence()` pour lier le justificatif.

### 3.5 Suppression d'occurrence par POST

`PlanningController` expose `@Post(':id/occurrences/:occurrenceId/remove')` en
plus du `@Patch` existant, les deux appelant `removeOccurrence()`. Le frontend
appelle en effet `POST` avec `{ revision }`.

## 6. Démarrage après intégration

```bash
# Backend
npm install
npx prisma migrate deploy   # applique 20261004000000_v53_geofence_punch
npx prisma generate
npm run seed
npm run start:dev           # http://localhost:3000

# Frontend
cd frontend
npm install
npm run dev                 # http://127.0.0.1:5173
```

Le frontend doit avoir `VITE_API_URL=/api` dans `frontend/.env` : le proxy Vite
transmet alors les appels au backend en conservant la **même origine**, condition
nécessaire au cookie de session `HttpOnly`.

> **Important** : si `VITE_API_URL` est vide, le frontend bascule en **mode
> maquette** (`usingMock`) et n'appelle jamais le backend.
