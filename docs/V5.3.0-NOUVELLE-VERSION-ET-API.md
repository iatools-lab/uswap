# uSwap v5.3.0 — Nouveautés, correctifs et documentation des API

> Document de référence de la version **`uswap-V5.3.0`**.
> Il détaille **tout ce qui a été ajouté ou corrigé** dans cette version ainsi que
> **l'ensemble des API (routes backend)** utilisées par le frontend et le backend.
>
> Versions précédentes : `uswap-frontend-s4.1.0`, `uswap-frontend-s5.1.0`, `uswap-v5.2`.

---

## 1. Vue d'ensemble

La version 5.3.0 marque l'**intégration complète du frontend et du backend** et
l'aboutissement des **User Stories 2069 à 2078**. Elle s'appuie sur le socle 5.2
et ajoute :

- le **reporting exportable** (CSV / XLSX) avec **audit des exports** ;
- les **rapports périodiques** avec **aperçu**, **historique d'exécution** et
  planification automatique ;
- le **calcul des heures** par station, semaine et mois ;
- la **visibilité de la synchronisation externe des congés** ;
- l'amélioration du parcours **hors ligne / PWA** (file d'absences annulable
  avant synchronisation, horodatage de synchronisation, notifications push).

Techniquement :

|---|---|
| Version | `5.3.0` (fichier `VERSION`) |
| Tag Git | `uswap-V5.3.0` |
| Backend | NestJS 11 · Prisma 6 · PostgreSQL |
| Frontend | React 19 · Vite 8 · TypeScript 5.8 |
| Branches | `danielle` (backend/intégration) → `develop` (intégration testée) |

## 3. Correctifs full-stack inclus

### 3.1 Authentification
- Liens d'activation corrigés : `/auth/activate?token=...`.
- La page d'activation accepte le token en **query string** et en **hash**.
- Activation : mot de passe hashé, compte actif, token consommé, sessions invalidées.
- Réinitialisation : gestion robuste du token et de l'expiration.
- **Envoi SMTP Gmail / Nodemailer** au lieu de Resend.
- Historique des invitations et réinitialisations (`CommunicationLog`).

### 3.2 Utilisateurs
- Vrai statut **`pending / active / inactive`** + champ `disabledAt`.
- Compteurs indépendants et filtres fonctionnels.
- Modification e-mail, nom, rôle, station, téléphone et adresse.
- Contrôle d'unicité de l'e-mail.
- Audit de modification renvoyé à l'interface.
- Correction des routes d'import (placées **avant** `/:id`).
- Historique de communication admin.

### 3.3 Planning / shifts
- Un poste peut être **vacant** (`Shift.swapperId` nullable).
- Dupliquer un poste crée réellement un poste vacant.
- Suppression d'une affectation supprime aussi l'attendance attendue.
- Affectation d'un swappeur **recrée** l'attendance attendue.
- Support réel des `templateIds` et `weekdays` lors de la génération.
- Correction **dimanche = 0** dans les jours de semaine.
- Permutation de deux occurrences via `swapWithId`.
- Contrôle de **révision** après modification.
- Planning mis à jour après ajout / suppression / permutation.
- Les plannings visibles par un swappeur sont **limités à ses propres shifts publiés**.

### 3.4 Notifications
- Préférences frontend **alignées** avec le contrat backend.
- Gestion `inApp / email / push / digest / quiet hours`.
- Abonnement push d'un appareil enregistré côté serveur (`PushSubscription`).
- Service worker prêt à afficher et ouvrir les notifications push.
- Les notifications in-app respectent la préférence utilisateur.

### 3.5 Hors connexion / PWA
- Suppression du cache de planning à la déconnexion.
- File offline conservée jusqu'à confirmation serveur.
- Déclarations d'absence avec `clientRef` idempotent (anti-doublon).

## 5. Documentation des API (routes backend)

Authentification : **JWT court** (`Authorization: Bearer …`) + **refresh token**
en cookie `HttpOnly`. Sauf mention contraire, les routes sont protégées par
`JwtAuthGuard` + `RolesGuard`.

Rôles : `ADMIN`, `SUPERVISOR`, `STATION_CHIEF`, `SWAPPER`.

## 6. Variables d'environnement

### Backend (`.env`)
```env
DATABASE_URL="postgresql://user:pass@localhost:5432/uswap"
JWT_SECRET="une-chaine-longue-et-secrete"
ACCESS_TOKEN_TTL_SECONDS=900
PORT=3000
CORS_ORIGIN="http://127.0.0.1:5173,http://localhost:5173"
FRONTEND_URL="http://127.0.0.1:5173"

# SMTP (Gmail / Nodemailer)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=adresse@gmail.com
SMTP_PASS=GOOGLE_APP_PASSWORD
MAIL_FROM=adresse@gmail.com

# Push (optionnel)
VAPID_PUBLIC_KEY=""
VAPID_PRIVATE_KEY=""
VAPID_SUBJECT="mailto:..."

# Intégration RH externe des congés (optionnel)
LEAVE_API_URL=""
```

> `SMTP_PASS` doit être un **Google App Password**, jamais le mot de passe Gmail normal.

### Frontend (`frontend/.env`)
```env
VITE_API_URL=/api
VITE_VAPID_PUBLIC_KEY=""
```


## 8. Sécurité — rappels

- Ne jamais commiter : `DATABASE_URL`, `JWT_SECRET`, clés SMTP/VAPID, mots de passe, fichiers `.env` réels.
- Ces valeurs vivent uniquement dans les `.env` locaux (exclus par `.gitignore`) ; utiliser `.env.example` comme référence.
- Aucune donnée personnelle de swappeur (email/téléphone) n'est incluse dans les exports.
